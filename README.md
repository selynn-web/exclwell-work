# 团队档案台 · 独立部署版

不需要 Claude 账号。数据存在你自己的 Supabase 项目里，网站托管在 Vercel。你已经有 Supabase / GitHub / Vercel 账号了，所以全程可以在浏览器里点完，不需要打开命令行、不需要装任何软件。

功能：会议记录 / SOP 管理 / 品质管理（检验记录、客户投诉记录、设备校准记录、设备维修记录、批次追溯）/ 产品损毁记录 / 追踪记录 / 汽车管理（路税、保险到期提醒）。SOP 附件支持任意格式（图片 / PDF / Word），单个文件仍限制 4MB 以内。数据每 20 秒自动刷新一次，别人改的东西你会陆续看到。界面支持中文 / English / Bahasa Malaysia 三语切换（登录页和侧边栏底部都有切换按钮），每个人可以选自己习惯的语言，互不影响。

**账号：每个人有自己的用户名和密码登录**（不再是团队共用一个密码），系统会记录每条记录是谁新增、谁最近修改的。`TEAM_PIN`（"团队邀请码"）现在只用在两个地方：管理员在「账号管理」里添加新成员时要输入一次，以及账号本人忘记密码、自助重设密码时要输入一次——**不能再靠邀请码在登录页自己注册一个全新的账号**，新成员的账号必须由管理员在「账号管理」里手动开通。日常登录用你自己设的用户名+密码。

> 如果你是第一次照着下面的步骤部署（全新的 Supabase / GitHub / Vercel 项目），按顺序做第一步到第五步。如果你已经部署过、只是要更新这次的新功能，直接跳到最下面「以后要改功能怎么办」——**这次更新不需要改任何 Vercel 环境变量、也不需要在 Supabase 建新表**，上传代码重新部署后，用你原来的用户名和密码正常登录就行，不用重新设置账号（这次更新把登录页原来"没有账号 / 忘记密码 / 新成员加入"的入口，改成了只做"忘记密码重设"，你已经有账号，不受影响；只有系统里完全没有任何账号时，这个入口才会用来创建第一个账号——细节见下面「打开使用、给自己和团队开账号」那节）。

## 第一步：在 Supabase 建一张表

1. 打开你的 Supabase 项目。
2. 左边菜单找「SQL Editor」，点「New query」。
3. 把下面这段贴进去，点「Run」：

```sql
create table if not exists kv_store (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz default now()
);
```

跑完不报错就行，这张表就是用来存整个团队档案台数据的。

## 第二步：拿到 Supabase 的连接信息

在同一个项目里，左边菜单「Settings」→「API」，你会看到两样东西：

- **Project URL**（类似 `https://xxxxx.supabase.co`）
- **service_role** 密钥（在「Project API keys」那一块，注意不是 `anon` 那个，是 `service_role`——这个权限比较高，只会用在服务器端，不会暴露给访问网站的人，但你自己也不要把它贴到网站上或者分享出去）

把这两个先复制到记事本备用，等下要填到 Vercel 里。

## 第三步：把代码传到 GitHub

1. 去 github.com 新建一个仓库（New repository），名字随便取，比如 `team-archive`，私有（Private）就行，不用勾选任何初始化选项。
2. 建完之后 GitHub 会显示一个空仓库的引导页，找到「uploading an existing file」这个链接点进去。
3. 把我给你的这个 `team-site` 压缩包解压后，**把里面的东西**（`public` 文件夹、`api` 文件夹、`package.json`、`README.md`、`.gitignore`，注意是这些文件本身，不是外层那层 `team-site` 文件夹）整个拖进浏览器的上传区域。
4. 拖之后确认一下左侧文件树里 `public/` 和 `api/` 是不是两个文件夹（里面还有子文件），如果 GitHub 把它们拆散摊平了，换成用 GitHub Desktop 这个客户端软件（desktop.github.com）操作会更保险——它能完整保留文件夹结构。
5. 拉到底部点「Commit changes」提交。

## 第四步：在 Vercel 导入这个仓库

1. 打开 vercel.com/dashboard，点「Add New」→「Project」。
2. 「Import Git Repository」里找到刚才那个 `team-archive` 仓库，点「Import」（如果没看到，先点「Adjust GitHub App Permissions」把这个仓库的访问权限给 Vercel）。
3. 不用改任何构建设置，往下找到「Environment Variables」，加这四个：

| 名称 | 值 |
|---|---|
| `TEAM_PIN` | 你自己定的团队密码，比如 `soy2026` |
| `AUTH_SECRET` | `3c7e7ab3a6d4f3d2ed16a32d28f79023e81727d7f00ebffd1fbb91a110eaea1e`（直接用这个就行，也可以换成自己的一长串随机字符） |
| `SUPABASE_URL` | 第二步复制的 Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 第二步复制的 service_role 密钥 |

4. 点「Deploy」，等一两分钟。

## 第五步：打开使用、给自己和团队开账号

部署完成后 Vercel 会给你一个网址（类似 `https://team-archive-xxxx.vercel.app`）。打开它，因为这是全新部署、系统里还没有任何账号，登录页点「忘记密码？点此重设」（这个入口在系统完全没有账号的时候，会自动变成"创建第一个账号"），输入：

- 团队邀请码：也就是你在第四步设的 `TEAM_PIN`
- 用户名（自己起一个，比如拼音，登录用）
- 密码（自己设，至少 4 位）
- 姓名（这一栏只有系统还没有任何账号时才会用到，用来创建的这第一个账号）

点「重设密码并进入」就开好账号、直接登录进去了——这是给你自己（管理员）开的第一个账号。**后面团队成员的账号只能由你（或者其他有账号管理权限的人）在「账号管理」里手动添加，不能靠他们自己拿着邀请码在登录页注册**——这是刻意这样设计的，防止邀请码万一传出去了，被不认识的人拿去随便开账号。

进去之后左边有个「账号管理」，可以看到所有已开通的账号，也可以在里面直接添加新成员（同样需要邀请码，但只有已经登录、并且有账号管理权限的人才能在这里添加）或者移除已经离职的人的账号（移除后对方不能再登录，但他之前保存过的记录不会被删除或改动）。

**已经有账号的人忘记密码怎么办**：登录页点「忘记密码？点此重设」，输入团队邀请码 + 自己的用户名 + 新密码就能重设，这个是保留的自助功能，不用找你。但如果输入的用户名系统里根本没有（比如想自己新开一个账号），会直接提示"还没有这个用户名的账号，请管理员在账号管理里帮你开通"，不会创建新账号。

### 限制某些人只能看到部分模块

添加新成员的时候，表单最下面有个模块勾选列表（会议记录、SOP、检验记录……）——不勾选任何一个，代表这个人不受限制，能看到全部内容（默认就是这样）；如果只想让他看到某几块，就把对应的模块勾上，保存后他登录进去左边只会看到你勾选的那几项，其他的（包括总览页的卡片）都不会出现，直接在网址里硬输入也进不去，是真的看不到、不是界面上藏起来而已。

已经开通的账号也可以随时调整：在「账号管理」里找到那个人，点「编辑权限」，重新勾选后点「保存权限」就行。限制的粒度是整个模块（比如"检验记录"整个板块），不能细到某一条具体记录；一个人能看到的模块，他在里面就可以正常新增/编辑/删除，不会有"只能看不能改"这种区分。

### 左边模块列表按部门分组

左边侧边栏里，「SOP 管理、检验记录、产品损毁记录」归在「品管部」这个小标题下面，「设备校准记录、设备维修记录」归在「维修部」下面，一眼就能看出这几块分别是哪个部门在用的。其他模块（总览、会议记录、客户投诉记录、批次追溯、汽车管理、追踪记录、请假管理、账号管理）不属于这两个分组，照旧平铺显示。

这个分组只是显示上的归类，不影响权限——如果某个账号被限制只能看"品管部"底下的某一项（比如只有 SOP 管理），登录进去就只会看到「品管部」这个小标题加上他能看的那一项，其他分组和模块完全不出现；如果他能看的模块刚好横跨两个分组，两个小标题都会各自出现在对应内容上面。手机屏幕上（窄屏时侧边栏会变成顶部横向滚动的一排），这些分组小标题不显示，跟以前一样是一排平铺的按钮，方便手指滑动查看。

有一点需要注意：如果你把自己的「账号管理」权限也取消勾选，系统会拒绝保存，并提示"不能取消自己的账号管理权限，请让其他同事帮你调整"——这是为了防止不小心把自己也锁在权限设置外面，进不去之后没人能帮你改回来。

### 语言切换（中文 / English / Bahasa Malaysia）

登录页和登录后侧边栏最下面都有一排"中文 / EN / BM"按钮，点一下整个界面就切换成对应语言（表单字段、按钮、状态、提示文字等基本都会跟着变）。这个选择是记在每个人自己浏览器里的，不是账号设置的一部分——同一个账号在不同电脑/浏览器登录，语言可以各选各的，互不影响；换个浏览器或清除过浏览器数据后，会恢复默认的中文，需要重新选一次。部门下拉建议、以及已经保存的记录内容（比如会议记录里填的具体文字）本身不会被翻译，只有界面上的文字标签、按钮、状态名称等会跟着切换。

### 设备维修记录（列表 + 日历两种查看方式）

「设备维修记录」用来登记设备坏了、修了什么、谁修的——设备名称、维修日期、故障描述、维修内容、维修人员、费用、状态（待维修 / 维修中 / 已完成）。

打开这个模块，标题旁边有个「列表 / 日历」切换：

- **列表**：跟其他模块一样，卡片形式一条条看，可以搜索、导出。
- **日历**：按月显示，哪天有维修记录，那天的格子上会有一个小圆点（颜色跟状态对应：黄=待维修、蓝=维修中、绿=已完成）。点一下有记录的日期，下面会出现这一天所有维修记录的详情，可以直接在这里点「编辑」修改；点一个没有记录的日期，会出现一个「+ 新建维修记录」按钮，日期已经帮你填好了。日历顶部有「‹ › 今天」可以切换上一个月/下一个月/回到本月。

**跟追踪记录是连着的**：新建/编辑一条追踪事项时，可以在"来源维修记录"这一栏选一条已有的维修记录关联起来；反过来，每条维修记录的卡片上如果有关联的追踪事项，会显示"N 项追踪"，点一下能跳过去看。维修记录卡片上还有个「+ 建追踪事项」按钮，点一下会直接建一条追踪事项、自动把设备名称和部门填好、并且自动关联这条维修记录——比如设备修了但零件要等货，就可以从这里一键建一条追踪事项跟进后续。

**可以拍照/上传照片**：表单最下面有「故障/维修照片」一栏，手机上点开会直接弹出拍照选项（也可以选相册里已有的照片），电脑上就是普通的选择文件。照片会显示在这条记录的卡片上（缩略图），点这条记录旁边的「编辑」还能看大图或换一张。选好照片后，浏览器会自动把它压缩一下再上传（长边缩到 1600 像素左右、转成 JPEG），肉眼基本看不出差别，但体积能小掉八九成——手机拍的照片经常有 3-4MB 甚至更大，压缩后一般也就几百 KB，这样既不容易碰到"文件太大"的提示，系统长期用下来也不会因为照片攒多了变卡。压缩后还是超过 4MB 的极少数情况，才会提示换一张再试。

### 产品损毁记录也能拍照

「产品损毁记录」表单最下面同样有一栏「损毁照片」，用法跟设备维修记录的照片完全一样——手机上直接拍、电脑上选文件都行，会自动压缩后再保存，照片会显示在卡片上。包装破损、品质不合格这类问题，拍张照片比纯文字描述更直观，以后要追溯或者跟供应商对质也有凭有据。

### 追踪记录（列表 + 甘特图两种查看方式）

「追踪记录」标题旁边跟设备维修记录一样，也有一个「列表 / 甘特图」切换：

- **列表**：跟之前一样，卡片形式一条条看，可以搜索、导出。
- **甘特图**：把每一条追踪事项画成一条横向的时间条，一眼看出谁在忙什么、什么时候到期、有没有重叠冲突。时间条的**起点是这条追踪事项的建立日期**，**终点是"预计完成日期"**（也就是本来就有的那个日期字段，没有新增任何要填的东西）。时间条的颜色跟状态角标是同一套颜色（黄=待处理、蓝=进行中、绿=已完成、红=已延误），点一下时间条就能直接打开这条记录编辑，鼠标停在上面会显示事项、部门、负责人、日期区间和状态的详细提示。图上有一条红色竖线标出"今天"，顶部工具栏可以按周/按月切换疏密、一键「回到今天」。左边的事项名称栏会一直固定在屏幕左侧，横向滚动时不会跟着跑掉。

**没填"预计完成日期"的追踪事项不会出现在甘特图上**（毕竟没有终点没法画），甘特图上方会有一行提示告诉你有几条这样的记录，去列表模式补上日期它们就会出现。

### 汽车管理（路税 / 保险到期提醒）

「汽车管理」用来登记公司每一辆车的路税和保险到期日——车牌号码、车型、使用部门、司机/使用人、负责人（用于 WhatsApp 提醒）、路税到期日、保险到期日、保险公司、状态（使用中 / 维修中 / 已停用）。

每辆车的卡片上会分别显示路税和保险两个到期状态角标：绿色代表还早（30 天以上）、黄色代表快到期（30 天以内，也就是提前一个月）、红色代表已经过期，一眼就能看出哪辆车要赶紧续。只要路税或保险任意一项**已经过期、或者在 1 个月（30 天）以内到期**（而且这辆车状态不是"已停用"），卡片上就会自动出现一个「📱 WhatsApp 提醒」按钮，用法跟追踪记录的提醒完全一样——点一下自动打开 WhatsApp，带好收件人和提醒内容（车牌、路税/保险到期情况、使用部门、司机），你看一眼确认没问题就能发送。提前一个月提醒是考虑到路税/保险续期本身需要一点前置时间，比追踪记录默认的 3 天提前量更宽裕。

**这里的"负责人"是单独一个字段**，不是"司机/使用人"——因为负责续路税/保险的人（比如行政/文员）不一定就是平时开这辆车的人，两个字段分开填，各司其职。提醒会发给"负责人"这一栏填的人，同样需要这个名字跟账号管理里的姓名完全对上才能自动找到手机号码（详见下面「WhatsApp 提醒」那节）。

### 人员管理已取消（数据仍然保留）

原来的「人员管理」模块已经从界面里拿掉了（改成用「账号管理」直接管理团队成员和手机号码，见上面「追踪记录的 WhatsApp 提醒」那节）。**如果你之前已经用人员管理保存过资料，这些资料不会被删除**，仍然完整保存在 Supabase 里（WhatsApp 提醒功能在账号管理里找不到号码时，还是会自动去这批旧资料里找一次），只是界面上没有地方再新增/查看/编辑它了。如果以后想彻底删除这批旧资料、或者想把它导出来看看还有什么内容，告诉我，我可以帮你处理。

### 导出成 Word 文档

每一条记录的卡片上都有个「导出」按钮，点一下会直接下载一个 `.doc` 文件，打开后是排版好的 Word 文档（表格形式列出这条记录的所有字段），可以用 Word、WPS、Google Docs 等打开，也可以直接打印或转发给别人。如果当前切换的是 English / Bahasa Malaysia 界面，导出的文档内容也会是对应语言。

每个模块页面顶部（搜索框旁边）还有个「导出全部」按钮，会把当前这个模块里**符合当前搜索/筛选条件**的所有记录，合并导出成一个 Word 文档，每条记录之间用标题分隔——适合月底/季度整理归档、或者要把某一类记录整体发给别人时用。如果这个模块目前没有任何记录，点这个按钮会提示"没有可导出的记录"，不会下载空文件。

### WhatsApp 提醒（追踪记录 + 汽车管理共用同一套机制）

追踪记录里，只要一条事项**已延误**、或者**预计完成日期在 3 天以内**（而且还没标记"已完成"），卡片上就会自动多一个"⏰"提醒角标和一个「WhatsApp 提醒」按钮。点一下按钮，会自动打开 WhatsApp（网页版或手机 App），并且**自动带好收件人和提醒内容**——提醒内容会自动写好追踪事项、部门、预计完成日期、进度备注。你只需要看一眼、确认没问题，点 WhatsApp 里的发送就行。

汽车管理的路税/保险到期提醒用的是完全一样的机制（见上面「汽车管理」那节），只是提醒内容换成了车牌、路税/保险到期情况；两个模块的「WhatsApp 提醒」按钮点法、号码查找方式都是一样的，以后如果还要给其他模块加类似的到期提醒，也是在这套机制上加，不用重新做一遍。

**⏰ 角标 / 按钮不出现，最常见的原因是这条追踪事项没有触发条件**——不是所有追踪事项都会显示提醒，只有满足下面任意一个才会出现：

1. "预计完成日期"已经填了，而且已经过了这个日期（还没标记"已完成"）；
2. "预计完成日期"已经填了，而且在未来 3 天以内；
3. 状态手动选成了"已延误"。

如果一条追踪事项**没填预计完成日期、状态也不是"已延误"**，就不会出现提醒——这是正常的，不是故障。新建/编辑这条追踪事项，把"预计完成日期"填上（或者把状态改成"已延误"），提醒就会出现。

**手机号码从「账号管理」来**：添加新成员时可以直接填手机号码；已经存在的账号，点「编辑权限」也能补上或修改手机号码。这个号码只用来给这个人发 WhatsApp 提醒，不影响登录。**追踪事项里"负责人"填的名字，要跟账号的姓名完全对上（一字不差）**才能自动找到号码；对不上、或者没填手机号，点提醒按钮时会提示你去账号管理补上，不会瞎发。

（如果你部署得比较早、之前用过已经取消的「人员管理」模块存过一些人的联系方式，那批旧资料系统还留着——账号管理里找不到号码时，会自动去那批旧资料里再找一次，不用重新填一遍。）

几点需要注意：

- **这是"一键发送"，不是自动群发**——不会有人在后台悄悄帮你发消息，每一条都是你自己点开、自己确认、自己按发送，跟你平时手动发 WhatsApp 一样，只是不用自己找人、不用自己打字。之所以选这个方式，是因为真正做到"到期自动发送、不用人碰"需要另外申请 WhatsApp 官方的 Business API（或者 Twilio 这类第三方服务），要企业认证、审核消息模板、按条计费，一般要等上几天到几周，对个人使用来说门槛太高，所以目前用这个免费、马上能用的方式。
- **号码格式**：本地手机号（比如 `012-3456789`）会被自动转换成马来西亚国际格式（`60123456789`）；如果本来就填了带国家代码的号码（比如 `+60123456789`），也能识别，不会重复加代码。如果号码写得比较特殊（比如混着写了好几个联系方式、或者不是纯数字），系统可能识别不出来，这时候点提醒按钮会提示你检查一下这个字段。
- 账号管理里新填的手机号码，正常情况下**保存后马上就能用**（不用等 20 秒自动刷新）；如果保存后立刻点提醒没反应，刷新一下页面再试。

这个功能是纯浏览器本地生成的，不经过服务器、不需要额外配置，也不会占用 Supabase 的空间——跟你之前部署的环境变量、数据表都没关系，直接上传这次的新代码就能用。下载下来的文件名统一是英文/数字（比如 `meetings_MTG-0001.doc`），这是因为部分浏览器在处理中文文件名时可能会出错导致下载失败，所以特意用英文文件名保证稳定；文档打开后里面的标题和内容还是完整的中文/英文/马来文，不影响使用。

### 删除记录有了「回收站」，删错了可以找回来

以前删除一条记录是真的直接没了。现在改成了软删除：点「删除」之后，这条记录会从列表里消失，但其实还留着，可以在这个模块页面标题旁边的「🗑 回收站」按钮里找回来（按钮上的数字代表回收站里有几条）。点开回收站，每条记录旁边有「恢复」和「彻底删除」两个按钮——「恢复」会让这条记录回到正常列表；「彻底删除」才是真的、无法挽回地删掉，而且只能对回收站里已经删除过一次的记录用，不会不小心把还在用的记录直接删没。

回收站是**按模块分开的**（比如"设备维修记录"删掉的东西在"设备维修记录"自己的回收站里，不会跟"追踪记录"的混在一起），而且只有对这个模块本身有权限的人才能看到、才能恢复或彻底删除，跟平时编辑这个模块需要的权限是同一套，没有额外单独开权限的步骤。

按钮上的数字（回收站里有几条）平时就看得到，但具体删了哪些记录，只有**点开「🗑 回收站」的那一刻才会去读取**，不是每次自动刷新都带着这批数据——这样删掉的记录（尤其是带照片的）攒得越来越多的时候，也不会拖慢日常使用。点开的瞬间会先显示"加载中…"，一般一两秒内就会出现具体内容，这是正常现象，不是卡住了。

### 每条记录能看到「修改历史」

编辑任意一条记录时，表单最下面会有一个可以点开的「修改历史」（后面括号里的数字是一共有几条历史）——点开能看到这条记录被谁在什么时候创建、改过几次、删除过/恢复过没有，每一行是"操作 · 操作人 · 时间"。这个历史最多保留最近 20 条（超过了会自动把最早的挤掉），只是留一个"谁在什么时候做了什么"的粗线条记录，不会去比对每个字段具体改了什么内容——如果以后真的需要精确到"这个字段从 A 改成了 B"这种程度，做起来工作量会大不少，先告诉我需求我再评估怎么加。

### 顶部有个全局搜索，一次搜全部模块

以前每个模块自己的搜索框只能搜自己模块里的记录。现在顶部（保存状态那一排的左边）多了一个"搜索全部模块…"输入框，打几个字，下面会弹出一个小窗口，列出所有模块里匹配到的记录（哪个模块、标题、编号），点一下就直接跳过去打开那条记录。这个搜索只会搜你自己账号有权限看的模块，其他模块的内容不会出现，也不会因为用了这个搜索框而绕过权限限制。

### 登录多次输错密码会暂时锁定

为了防止有人在登录页反复乱试密码硬猜，连续输错 5 次密码（或者团队邀请码），这个账号（或者邀请码）会被暂时锁定 15 分钟，锁定期间就算后面输对了也会先提示"尝试次数过多，请稍后再试"，过了 15 分钟自动解锁，不需要谁手动去解。正常使用（比如忘了密码想起来又打对了）不会触发这个限制，只有连续错很多次才会。

### 邮件提醒（每天自动发送，不用人点）

前面的 WhatsApp 提醒都是"一键发送"——需要有人自己点开、自己确认、自己按发送。邮件提醒不一样：**设置好之后，系统每天会自己检查一遍追踪记录、汽车管理的路税/保险到期、设备校准记录，把该提醒的都汇总进一封邮件，自动发出去，不需要任何人点任何东西**。检查范围是：

- 追踪记录：已延误、或者 3 天以内到期的
- 汽车管理：路税或保险已过期、或者 1 个月以内到期的
- 设备校准记录：已过期、或者 14 天以内到期的（跟卡片上黄色角标出现的时机一致）

如果当天没有任何符合条件的事项，就不会发邮件（不会天天发一封空的来打扰你）。这个功能默认是关闭的，需要按下面的步骤开通；不开通的话不影响其他任何功能。

**第一步：注册 Resend（免费发邮件的服务，不需要企业认证）**

1. 打开 [resend.com](https://resend.com)，用你的邮箱注册一个免费账号。
2. 登录后，左边菜单找到「API Keys」，点「Create API Key」，名字随便起（比如 `team-archive`），权限用默认的就行，点创建。
3. 创建后会显示一长串以 `re_` 开头的字符串——**这个只会显示这一次，马上复制保存好**（比如先粘贴到记事本里）。这个字符串不能贴在聊天里，等下要直接填进 Vercel。如果不小心没复制到，删掉这个 key 重新建一个就行，免费不限次数。

**第二步：在 Vercel 加两个环境变量**

回到 Vercel 项目的「Settings → Environment Variables」（跟第四步设 `TEAM_PIN` 那几个是同一个地方），加上：

| 名称 | 值 |
|---|---|
| `RESEND_API_KEY` | 第一步复制的 `re_` 开头的字符串 |
| `REMINDER_EMAIL_TO` | 接收提醒邮件的邮箱地址——**必须跟你注册 Resend 时用的邮箱一模一样**（原因见下面「关于收件邮箱的限制」），如果想发给多个邮箱，用英文逗号隔开 |
| `CRON_SECRET` | 随便一串自己编的随机字符（比如 30 位英文数字混着打），只是用来确认"每天自动触发的请求确实是 Vercel 自己发的"，不用记住，设一次就行 |

加完之后回到「Deployments」标签，点最新那条右边的「···」→「Redeploy」，让这几个新的环境变量生效。

**第三步：测试是否设置成功**

重新部署完成后，打开网站、进「账号管理」，最上面「添加团队成员」下面会有一个「邮件提醒」的小面板，点「发送测试提醒邮件」——如果设置对了，`REMINDER_EMAIL_TO` 填的邮箱几秒内就会收到一封测试邮件（如果当时正好有到期事项，收到的会是真的提醒内容，不是"测试邮件"那几个字，这也说明是正常工作的）。没收到的话，多半是上面两个环境变量哪个填错了，或者忘了重新部署。

**关于收件邮箱的限制**：Resend 免费版默认只允许把邮件发到"你注册 Resend 账号时用的那个邮箱"，这是 Resend 自己的限制，不是这个系统的限制。所以 `REMINDER_EMAIL_TO` 要填跟注册 Resend 用的同一个邮箱才会正常收到；如果以后想发给别的邮箱（比如好几个管理员都要收），需要在 Resend 后台「验证一个域名」（需要能操作那个域名的 DNS 设置，Resend 后台有对应教程，会比现在麻烦一点），到时候需要的话告诉我，我再帮你调整代码里发件人那部分。免费版每天最多发 100 封、每月最多 3000 封，一个每天一封的提醒摘要完全用不完这个额度。

**自动发送的时间**：设置在每天马来西亚时间早上 9 点左右自动检查一次（Vercel 免费版对触发时间没法保证精确到分钟，可能会在 9 点到 10 点之间的任何时候实际触发，这是 Vercel 那边的机制，不是系统故障）。

**这个功能是真正自动的，跟 WhatsApp 提醒的定位不一样**：WhatsApp 那套是"帮你省打字的时间，但发不发、发给谁，还是你自己确认"；邮件这套是"完全不需要人在场"，适合当作一个兜底——就算大家都没空一条条去点 WhatsApp 提醒，至少每天有一封邮件汇总提醒着该续的路税、该完成的任务不会被彻底忘掉。

### 这次顺便做的几个"省流量"优化

这几个都是内部效率上的调整，不需要你做任何设置，用起来的感觉基本跟以前一样，只是长期用下来会更轻快：

- 照片上传前自动压缩（见上面"设备维修记录"那节）。
- 回收站的具体内容改成点开才读取，不再是每次自动刷新都带着（见上面"回收站"那节）。
- 页面每 20 秒自动刷新一次，以前不管数据有没有变都会重新整个刷一遍；现在如果跟上一次完全没变化，就直接跳过，不会有画面"闪一下"的感觉，也顺带修好了一个小毛病——之前如果你正开着"修改历史"面板看，20 秒后会被自动刷新悄悄收起来，现在不会了。

### 总览页加了几张图表

打开网站默认看到的「总览」页面，以前只有一排数字卡片。现在数字卡片下面多了一块「数据概览」，用图表的方式再看一眼同样的数据——各模块记录数量的横向条形图、追踪记录当前状态分布（待处理/进行中/已完成/已延误各占多少）、产品损毁记录最近 6 个月的趋势。这些图表是根据你已经有的数据自动生成的，不需要额外填什么、也不会因为图表而多存一份数据；如果某个模块暂时完全没有记录，对应的图表会自动不显示，不会挂一个空白图表在那里。

### 设备二维码——贴在设备上，扫一下直接看维修/校准记录

设备维修记录、设备校准记录里，每张卡片现在多了一个「🔲 二维码」按钮。点开会弹出这台设备专属的二维码，加上这台设备最近的维修记录和校准记录列表，还能直接从这里新建一条新的维修/校准记录（会自动带上设备名称，不用重新打一遍）。二维码框旁边有「🖨 打印」按钮，可以直接打印出来贴在设备本体上——以后维修师傅站在设备前面，手机扫一下贴纸上的码，不用登录后再去列表里一条条找，直接就跳到这台设备的记录页面（如果当时还没登录，会先跳去登录页，登录完自动继续跳过去，不用重新扫一次）。

设备是靠「设备名称」这个字段配对的：维修记录和校准记录里，只要设备名称打的是同一个（大小写、前后空格不算数，比如"搅拌机1号"和"搅拌机1号 "会被当成同一台），二维码扫出来的页面就会把两边的记录都列出来。如果同一台设备在不同记录里名字打法不统一（比如有时候打"1号搅拌机"有时候打"搅拌机一号"），系统没办法自动识别成同一台，建议往后尽量统一着打。

二维码本身是纯浏览器本地生成的图案，不经过任何第三方服务，也不需要联网生成，扫描出来的链接就是这个网站自己的地址，不会跳去外部网站。

### 记录可以留言讨论了

打开任意一条记录（不只是设备维修/校准，所有模块都有），表单最下面、「修改历史」下面多了一个「留言」区——可以在这里跟同事就这条记录本身讨论，比如"零件已经订了，周五到"这种进度备注，不用另外开微信群或者写在备注栏里跟正式数据混在一起。谁都可以留言，也可以删除自己或别人手滑发错的留言（跟这个模块本身的编辑权限是同一套，不需要额外设置）。留言最多保留最近 50 条，超过了会自动把最早的挤掉——如果哪条记录留言真的攒到 50 条，多半说明这条记录该单独拉出来另开个追踪事项跟进了。

### 设备校准到期后，会自动帮你建好下一条草稿记录

以前一条校准记录到期了，得有人自己记得去手动建一条新的。现在改成：**每天自动检查一次**（跟上面邮件提醒是同一次检查，但这个功能不需要开通邮件提醒也会跑），只要发现某条校准记录的「下次到期日期」到了或者已经过了，就会自动生成一条新的草稿记录——设备名称、类型、执行单位都会从上一条带过来，方便你确认是不是同一个供应商；执行日期和结果留空，等真正做完校准之后再回来把这些实际信息填上、顺便把「下次到期日期」重新设一个新的。这条自动生成的草稿卡片上会有一个「自动生成的草稿」的浅色标签，跟手动建的记录一眼就能分清楚。

这个是纯粹的"提醒兜底"，不会重复生成——同一条到期记录只会生成一次草稿，不会每天都多冒出一条来；只有等你把这条记录的「下次到期日期」改成一个新的日期之后，等那个新日期到了才会再生成下一条。

### 支持手机上「添加到主屏幕」

现在手机浏览器打开这个网站，可以把它添加到手机主屏幕，图标点开跟一个独立 App 差不多（没有浏览器地址栏，看着更像自己的系统）：

- **安卓 / Chrome**：打开网站后，浏览器右上角菜单里通常会有「添加到主屏幕」或「安装应用」的选项（有些手机也会自动弹出提示），点一下确认就行。
- **iPhone / Safari**：打开网站后，点底部分享按钮（方框加箭头那个图标），下拉找到「添加到主屏幕」。iPhone 只有用 Safari 打开才会有这个选项，微信内置浏览器或者其他 App 里打开是看不到的。

添加之后主屏幕上会有一个深绿色底、写着"档"字的图标，点开就是网站本身，日常使用不用每次都从浏览器书签里找。这纯粹是个方便入口，不是把系统变成"离线也能用"——没有网络的时候还是打不开、看不到数据，这点没有变。

### 设备总览页——按设备汇总维修+校准记录

侧边栏"维修部"分组里，设备校准记录和设备维修记录上面多了一个「设备总览」。这个页面不是新的数据，是把这两个模块里已经填过的记录，按「设备名称」自动归到一起——一台设备一张卡片，能看到这台设备一共有几条记录、最近一次是什么时候、下次校准到期日期、还有没有维修中/待维修的事项没处理完。点开卡片就是这次前面做的那个设备二维码面板，能直接看这台设备的详细记录、打印二维码。

跟二维码功能一样，这里也是靠「设备名称」这个字段自动配对的——同一台设备在维修记录和校准记录里，名字要打得一致（大小写、前后空格不算数），才会被认成同一台设备汇总在一起。这个页面能看到什么，跟你账号本身对"设备维修记录"和"设备校准记录"这两个模块的权限是一致的，没有单独的权限设置，被限制了看不到这两个模块的账号，侧边栏也不会出现这个入口。

### 总览页顶部加了"需要关注"清单

以前总览页只有统计数字和图表，具体是哪几件事要处理，得点进对应模块自己看角标。现在总览页最上面多了一块「需要关注」清单，把追踪记录的延误/即将到期事项、设备校准到期、车辆路税/保险到期这三类，汇总成一个可以直接点的列表——越紧急（已经逾期的）排得越靠前，颜色也更深。点一下某一项，会直接跳到对应模块、打开那条记录，不用自己去翻列表找。如果当前完全没有需要关注的事项，这块区域会自动不显示。

这块清单跟前面"邮件提醒"检查的是同一批条件（追踪记录 3 天内到期、设备校准 14 天内到期、车辆 30 天内到期），只是一个是每天自动发一封邮件，一个是打开网站当下就能看到——两个搭配起来用：邮件负责"就算没人开网站也有个兜底提醒"，这个清单负责"打开网站的时候一眼就知道该处理什么"。

### 一键导出全部数据备份

「账号管理」页面里，添加团队成员那块下面多了一个「数据备份」面板，点「下载全部数据备份」会把你账号当前能看到的全部模块记录打包成一个文件下载到你自己电脑上——留一份自己手上的备份，不依赖网站、不需要联网就能打开看（用记事本或者其他能打开 JSON 文件的工具）。这个不会包含回收站里已经删除的记录（如果有需要备份的，先去对应模块回收站里恢复出来）；导出的内容跟你账号本身的权限一致，被限制的账号只能导出自己能看到的那部分模块，不会把整个系统的数据都导出来。

下载下来的文件名是英文的（比如 `team-archive-backup_2026-09-01.json`），原因跟前面 Word 导出功能一样——部分浏览器处理中文文件名时会出错，所以用英文文件名保证下载稳定，文件里面的实际内容还是完整的中文/英文/马来文数据，不影响使用。这个功能主要是给你自己留一份安心的副本，不是要取代 Supabase 那边本身的数据保存机制。

### 设备保养清单——一次性导入了扫描件整理出来的 106 条参考记录

侧边栏"维修部"分组里，「设备总览」和「设备校准记录」中间多了一个新模块「设备保养清单」。这是根据你之前上传的《Preventive Maintenance Checklist》扫描件整理出来的——按检查频率（每周/每两周/每月/每两月/每三月）再按地点分组，每台设备一条记录，字段包括设备编号、中英文名称、地点、检查项目、备注（少数设备有的附加检查项），以及上次保养日期、下次到期日期（这两个先留空，你确认好实际排班之后随时可以逐条补上）。

第一次打开这个模块、还没有任何记录的时候，工具栏会有一个「📋 导入参考清单（106 项）」按钮，点一下、确认一次，就会把这 106 条记录一次性建好——不用一条条手动输入。每条记录状态都会先标成「未核对」（橙色角标），提醒你这是从扫描件人工转录出来的，正式使用前建议对照原始检查表核对一遍，尤其是设备编号；核对没问题之后，把状态改成「已核对」就行，跟其他记录一样可以单独编辑、留言、查看修改历史、删除后进回收站。如果这个模块已经有记录了，再按一次导入按钮会先提示"可能造成重复"，需要你再确认一遍才会继续，避免手滑重复导入。

这份清单目前是独立的模块，还没有跟"设备总览"页（按设备名称汇总维修+校准记录）打通——两边用来配对设备的字段不一样（总览页按"设备名称"自由文本配对，这里是"设备编号"），强行拼在一起容易配错，所以先保持独立。总览页顶部的"需要关注"清单已经顺带覆盖了这个模块（有设定下次到期日期、且 14 天内到期或已逾期的会自动出现），但**没有**接入每天自动发送的邮件提醒——因为导入进来的 106 条记录到期日期都是空的，先接进邮件也不会有效果，而且免得以后一次性补日期时突然多出上百条到期提醒把邮件"炸"了。等你把各设备的实际保养日期陆续填上、觉得该提醒了，告诉我，我再把这个模块也接进每天的邮件提醒里。

「导入参考清单」按钮在两个地方都能找到：模块顶部工具栏（搜索框和"导出全部"旁边），以及模块还没有任何记录时中间空白区域会额外放大显示一次，比较显眼。如果打开"设备保养清单"这个页面之后完全看不到这个模块或者这个按钮，按顺序检查：① GitHub 那边的文件是不是已经全部覆盖上传成功、Vercel 是否已经重新部署完成（项目页面「Deployments」标签能看到最新一次的时间和状态）；② 浏览器有没有缓存住旧版本，试试强制刷新（Windows 用 Ctrl+Shift+R，Mac 用 Cmd+Shift+R）；③ 如果登录的这个账号之前被"限制模块"过（账号管理里勾选过只能看哪几个模块），新增的"设备保养清单"不会自动补进已经保存的权限里，需要去账号管理找到这个账号、点「编辑权限」，要么重新勾选包含"设备保养清单"，要么把勾选全部取消（不勾选=不限制，可看全部模块）。

## 客户投诉记录——可以拍照、也能单独填写解决方案

「客户投诉记录」现在可以上传/拍照相关照片了（比如有问题的产品、包装），跟设备维修记录的拍照附件用法一样，最大 4MB。另外新增了一个「解决方案 / 结果说明」字段，跟原本的"处理措施"分开——"处理措施"记录的是处理过程中做了什么，"解决方案 / 结果说明"专门写最终怎么处理的、给客户的答复或赔偿方式、问题是不是已经解决，方便日后回看一条投诉时一眼看到结果，不用从头翻处理过程。已经存在的旧投诉记录不受影响，这两个新字段留空，打开编辑随时可以补上。

## 账号可以加个人邮箱了

「账号管理」里，添加团队成员的表单、以及每个账号的「编辑权限」面板，手机号码旁边现在多了一个「个人邮箱」输入框（选填）。跟手机号码一样，只是存起来、显示在账号卡片上，目前**没有**接到任何自动发信功能上——比如每天的邮件提醒目前还是发到 Vercel 环境变量 `REMINDER_EMAIL_TO` 设置的那个/那些收件地址，不会自动改成读取每个人账号里填的邮箱。如果之后想让邮件提醒改成按人分别发送、或者这个邮箱要用在别的地方，告诉我，我再接上。

## 以后要改功能怎么办

之后有新需求告诉我，我把改好的文件发给你，你回到 GitHub 那个仓库页面，用同样的「Upload files」方式把改动过的文件重新拖上去覆盖、提交——Vercel 检测到 GitHub 仓库有新提交会自动重新部署，你不需要再去 Vercel 那边点任何东西。这一步也只能由你（或团队里管这个仓库的人）来做，我这边没有权限直接帮你们推送代码。

## 遇到问题

- 打开网站一直转圈或报错：多半是第四步的四个环境变量哪个填错了或漏填了，回 Vercel 项目的「Settings → Environment Variables」检查，改完后需要重新部署一次（项目页面「Deployments」标签，点最新那条右边的「···」→「Redeploy」）。
- 登录页提示"服务器未配置"：说明 `TEAM_PIN` 或 `AUTH_SECRET` 没设对。
- 保存数据时报错：多半是 Supabase 那两个值填错了，或者第一步的表没建成功，回 Supabase 的「Table Editor」确认能看到 `kv_store` 这张表。
- 用户名或密码忘记了：回登录页点「忘记密码？点此重设」，用团队邀请码（`TEAM_PIN`）+ 同样的用户名重新设一次密码就行，不影响你之前保存的记录；如果用户名本身也记不清了，去「账号管理」里核对一下（或者请其他有账号管理权限的同事帮忙看）。
- 团队邀请码本身忘记了 / 想换掉：回 Vercel 环境变量把 `TEAM_PIN` 改掉，重新部署一次，新邀请码告诉需要用到它的人（管理员添加新成员、或者有人要重设密码时）就行——只影响以后开新账号/改密码，已经登录过的人不受影响，不用重新登录。
- 新成员没法自己在登录页开账号了：这是刻意的——账号现在只能由已经有账号管理权限的人，在「账号管理」里手动添加。如果对方点「忘记密码？点此重设」输入一个系统里还没有的用户名，会看到"还没有这个用户名的账号"的提示，这不是故障，去账号管理帮他加一个就行。
